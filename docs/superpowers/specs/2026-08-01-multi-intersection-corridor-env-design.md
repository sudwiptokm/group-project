# SP1 — Multi-intersection arterial corridor environment (design)

**Date:** 2026-08-01
**Status:** Design approved, pending spec review
**Sub-project:** SP1 of the multi-intersection coordinated-MARL thesis extension

## Context

The current project delivers a fair, tuned comparison of four single-agent RL
algorithms (DQN, QR-DQN, PPO, A2C) against a fixed-time baseline on **one**
4-arm intersection, across two demand scenarios (peak/offpeak), with a
safety-aware λ-weighted reward (`diff_waiting − λ·safety`). That work is complete
and validated (`results/comparison_stage1.csv`, `docs/RESULTS_WRITEUP.md`).

The identified thesis-level gap is **generalization**: a single isolated
intersection is not a network. The chosen extension is a **multi-intersection
arterial corridor** with the research contribution *"explicit coordination
(CTDE) beats independent agents and classical baselines."*

That full extension is too large for one spec. It is decomposed into:

- **SP1 — Multi-intersection environment** *(this spec)*: corridor network,
  multi-agent PettingZoo env, non-RL coordinated baselines. Foundation.
- SP2 — Independent multi-agent RL (per-signal agents, parameter sharing).
- SP3 — Coordination method (CTDE: MAPPO/QMIX) — the research contribution.
- SP4 — Safety-aware λ reward extended to the network.
- SP5 — Experiments + analysis (scenarios, seeds, compare, plots).

Each sub-project gets its own spec → plan → implementation cycle.

## Scope of SP1

**In scope:** a runnable arterial corridor SUMO network; peak/offpeak route
files; a multi-agent env exposing a raw PettingZoo `ParallelEnv`; two non-RL
coordinated baselines (fixed-time green-wave, max-pressure); network-level
metrics plumbed through the existing eval-CSV + comparison path; smoke tests.

**Explicitly out of scope (deferred):** any RL training; the CTDE method; the
MARL framework choice (RLlib vs EPyMARL vs custom — decided at SP2/SP3);
hyperparameter tuning; the full experiment runs. SP1 delivers the substrate that
those consume, and nothing more.

**Success criterion for SP1:** an RL-free corridor on which both baselines run
end-to-end and emit network + per-intersection metrics through `compare.py`, and
a PettingZoo env whose `reset()`/`step()` produce correct per-agent
observation/reward shapes for N agents. No learning is required to close SP1.

## Design

### 1. Network — `corridor.net.xml`

- **3 signalized 4-arm intersections** in a line along a main arterial (E↔W),
  each with a minor cross-street (N↔S). 3 nodes is the minimum that exhibits
  green-wave propagation (upstream → mid → downstream) while keeping compute and
  tuning tractable; the design must extend to 4+ by adding nodes/edges only.
- **~200 m** inter-signal spacing on the arterial (tunable; chosen so a platoon
  released at one signal arrives at the next within a plausible offset window).
- Per-node geometry, lane counts, and speeds **reuse the existing single
  intersection** (`intersection.net.xml`) so results stay comparable and the
  heterogeneous-vehicle / sublane setup (`vtypes.add.xml`) carries over unchanged.
- Build via `netgenerate` (grid/spider template trimmed to a line) or hand-authored
  nod/edg/con files, whichever reproduces the existing junction geometry more
  faithfully. Each intersection keeps an independent `tlLogic` (one RL agent per TLS).

### 2. Demand / routes — `corridor_peak.rou.xml`, `corridor_offpeak.rou.xml`

- Mirror the current two-scenario structure (peak / offpeak) and the existing
  vehicle-type mix.
- **Dominant arterial through-flow E↔W** (the platooned demand green-wave
  serves) plus **cross-street demand** entering at each node.
- Generated by extending the `make_scenarios.py` pattern to the corridor
  (`SCENARIO_ROUTES`-style mapping gains corridor entries).
- Calibrate flows so that **platoons form and independent per-signal control
  leaves coordination gains on the table** — i.e. green-wave / CTDE has something
  measurable to exploit. Sanity-check with a short fixed-time run before locking.

### 3. Multi-agent env — `make_corridor_env`

- New constructor `make_corridor_env(seed, scenario, lam, gui, out_csv)` mirroring
  the signature of the existing `make_env`, but wrapping sumo-rl with
  **`single_agent=False`**, yielding a **PettingZoo `ParallelEnv`** with one agent
  per traffic light.
- **Per-agent observation:** the existing `PCUObservationFunction` (phase
  one-hot + min-green flag + PCU density + PCU queue), applied per TLS. Agents are
  **homogeneous** (identical obs/action spaces) so SP2 can use parameter sharing.
- **Per-agent reward:** the existing safety-aware reward
  (`make_safety_reward_fn(lam)`), computed **locally per intersection** — same
  `diff_waiting − λ·safety` form used single-agent, so λ semantics are unchanged.
- **`SafetyLoggingEnv` extended to multi-TLS:** record safety sub-terms
  (emergency braking, intersection exposure) **per agent** and as a **network
  aggregate**, keyed by TLS id, preserving the current single-agent CSV columns as
  the aggregate.
- **`EPISODE_SECONDS`** env var reused for episode length.
- **Framework-agnostic:** SP1 exposes only the raw PettingZoo env. Adapters for a
  specific MARL framework (RLlib `MultiAgentEnv`, EPyMARL, or a custom loop) are
  written in SP2 against this stable interface.

### 4. Baselines (non-RL)

Both are learning-free references the coordination claim must beat, and both run
through the **same eval-CSV path** as `baseline.py` so their metrics are directly
comparable to RL results:

- **Fixed-time green-wave** — coordinated signal offsets computed from the
  free-flow corridor travel time between adjacent signals (classic bandwidth /
  offset design). This is the "coordination without learning" reference.
- **Max-pressure** — the standard strong decentralized TSC baseline (each signal
  greedily serves the movement with maximum pressure; no learning, no explicit
  communication). A credible comparator examiners expect alongside fixed-time.

New entry point `corridor_baseline.py --scenario <s> --controller <green_wave|max_pressure> --seed <n>`,
writing `logs/eval_<controller>_<scenario>_seed<n>_*.csv` in the existing format.

### 5. Metrics

- **Network-level:** total & mean travel time, throughput (vehicles arrived),
  mean waiting time, and **corridor stops** (number of stops along the arterial —
  the direct green-wave quality signal).
- **Per-intersection breakdown** of the above + the safety sub-terms.
- `compare.py` extended to aggregate corridor/network metrics and to emit a
  network-level comparison row per (scenario, λ, controller/algo), preserving the
  existing single-intersection columns where meaningful.

### 6. Testing

- **Env smoke test:** `reset()` returns one observation per agent with the
  expected shape; `step(actions)` accepts a dict of N actions and returns
  per-agent obs/reward/termination of correct shapes; the episode terminates at
  `EPISODE_SECONDS`; two runs with the same seed are identical.
- **Baseline smoke test:** each controller runs a short episode on each scenario
  and produces finite, non-degenerate network metrics (throughput > 0, travel
  time finite).
- **Regression guard:** the single-intersection pipeline is untouched — existing
  tests still pass.

## Data flow

```
corridor.net.xml + corridor_<scenario>.rou.xml
        │
        ├── make_corridor_env(...)  ──► PettingZoo ParallelEnv (N agents)
        │        (obs: PCUObservationFunction per TLS)
        │        (reward: make_safety_reward_fn(lam) per TLS)
        │        (SafetyLoggingEnv: per-agent + network-aggregate CSV)
        │                                   │
        │                                   ▼  (consumed by SP2+ RL training)
        │
        └── corridor_baseline.py (green_wave | max_pressure)
                 │
                 ▼
        logs/eval_<controller>_<scenario>_seed<n>_*.csv
                 │
                 ▼
        compare.py (network-aggregate) ──► logs/comparison.csv ──► plots.py
```

## Components & boundaries

| Component | Responsibility | Depends on |
|-----------|----------------|------------|
| `corridor.net.xml` (+ nod/edg/con) | Static 3-signal arterial geometry | reuses `intersection.*` geometry, `vtypes.add.xml` |
| `make_scenarios.py` (extended) | Emit `corridor_<scenario>.rou.xml` | network edges |
| `make_corridor_env` | PettingZoo multi-agent env + safety-λ reward/obs/logging | `PCUObservationFunction`, `make_safety_reward_fn`, `SafetyLoggingEnv`, sumo-rl |
| `SafetyLoggingEnv` (extended) | Per-agent + network safety logging | sumo-rl |
| `corridor_baseline.py` | Green-wave + max-pressure controllers → eval CSV | network, traci |
| `compare.py` (extended) | Aggregate network metrics into comparison table | eval CSVs |

Each unit has one purpose and communicates through files (net/route XML, eval
CSVs) or the PettingZoo interface — so SP2+ can be built and tested against SP1
without reading its internals.

## Risks & mitigations

- **sumo-rl multi-agent quirks** (`single_agent=False` obs/reward dict shapes,
  per-agent min-green handling) — mitigate with the env smoke test before any RL
  work; validate against a trivial random-action rollout.
- **Route calibration** — if flows are too light, coordination shows no gain and
  the thesis claim is unmeasurable; if too heavy, gridlock masks it. Mitigate by
  sanity-checking green-wave vs fixed-uncoordinated fixed-time on the corridor
  during SP1 and tuning demand until a coordination gap is visible.
- **Max-pressure correctness** — it is easy to implement a subtly wrong pressure
  definition; mitigate by unit-testing pressure computation on a hand-checked
  toy state.
- **Metric comparability** — network metrics must not silently break the existing
  single-intersection `compare.py` output; mitigate with the regression guard.
